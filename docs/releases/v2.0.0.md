# tincan v2.0.0

Released September 8, 2026.

Launch other agents from your MCP client, keep their listeners available, and
collect work after reconnecting. v2 brings the hosted-listener and MCP features
developed since v0.1.0 into a tagged release.

## What's new

- Eight stdio MCP tools: discover presets, launch, send, wait, inspect status,
  cancel, reset and stop. Each server is bound to one project room.
- Hosted workers for Claude, Codex, Grok, Agy, Kimi and Gemini. Linux/macOS can
  launch workers without a terminal per agent; Windows can run foreground hosts.
- Persistent conversations for the native Claude, Grok, Agy and Kimi presets,
  with explicit session IDs, reconnect, restart and reset. Codex, Gemini and
  custom commands default to stateless execution.
- Durable request IDs, bounded waits and progress cursors. A client disconnect
  or wait timeout does not cancel the task or submit it again.
- Authenticated host ownership and shutdown, durable delivery claims,
  cancellation of owned process trees, and explicit interrupted outcomes.
  Work with uncertain side effects is never replayed automatically.
- Bounded output, private runtime paths, rejected unsafe spool entries, and
  garbage collection that preserves active work. Windows state replacement
  handles concurrent readers and process checks recognize exited processes.
- Updated tell/listen skills, safe installation into aliased skill directories,
  version metadata, and release publishing gated on tests of the tagged commit.

The [setup guide](https://github.com/c0ze/tincan/blob/v2.0.0/docs/setup.md) includes client configuration, session prompts and
provider authentication troubleshooting. The [protocol](https://github.com/c0ze/tincan/blob/v2.0.0/PROTOCOL.md)
documents every command, tool and lifecycle rule.

## Upgrading

Download the archive for your OS and architecture from the
[v2.0.0 release](https://github.com/c0ze/tincan/releases/tag/v2.0.0) and verify it
against `checksums.txt`, or install with Go 1.25 or newer:

```sh
go install github.com/c0ze/tincan/v2/cmd/tincan@v2.0.0
tincan version --format json
```

The Go module is now `github.com/c0ze/tincan/v2`. The old
`github.com/c0ze/tincan/cmd/tincan@latest` install command does not upgrade to v2.
Use `/v2/cmd/tincan@latest` for future stable v2 releases. The executable is still
named `tincan`; CLI command names and room selection remain unchanged.

Update any MCP configuration that points at a different binary. Let active
work finish, stop existing hosted listeners with `tincan down <name> --room
<path>`, and reconnect the MCP client before launching workers with the new
binary. Replacing the executable does not upgrade a running host. Retain the
room's request records and session pointers; do not clear `.tincan/` as an
upgrade step. Install refreshed skills with `./install.sh --skills-only` from
the v2 checkout and restart sessions that need to rediscover them.

Ordinary legacy message envelopes remain supported. v2 validates portable
names, regular files and envelope sizes more strictly, and requires a local
filesystem with hard-link support. Existing custom presets must match the
installed provider CLI; remove manually configured resume/output flags before
selecting a persistent adapter.

## Compatibility and limits

- Release binaries target Linux, macOS and Windows on amd64 and arm64.
- Windows detached launch is unsupported. Start `tincan serve` in a terminal
  before connecting to that host through MCP.
- Provider executables and their credentials are separate installations. tincan
  launches those executables per turn; it does not automate desktop windows or
  supply provider SDK/ACP backends.
- Rooms are local to one computer. This release does not connect remote rooms
  or make a local MCP server available to a cloud harness.
- Cancellation cannot roll back a worker's previous edits. Interactive
  `/listen` receivers cannot honor targeted MCP cancellation.

## Validation

Release publication requires vet, build and race-enabled tests on Linux,
macOS and Windows using both Go 1.25 and stable Go, plus installer and platform
stress checks. GoReleaser builds all six archives and publishes SHA-256 checksums.
The [validation record](https://github.com/c0ze/tincan/blob/v2.0.0/docs/reviews/2026-09-08-stability-mcp-validation.md)
documents native CI and live Claude/Codex/Grok/Agy/Kimi checks on Linux and macOS,
including persistent-provider reconnect and the macOS Claude authentication fix.
